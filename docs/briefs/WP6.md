## Evaluation (`backend/src/gwylio/evaluation/`, pure functions over plain
inputs; the infrastructure layer fetches rows and hands them in)

`funnel.py`

- `FunnelTrend(runs: sequence of (run_id, started_at, funnel, requests_made,
  budget_exhausted))` with `latest()`, `series(field)` and
  `disposition_summary(run_id, dispositions)` (counts per outcome, plus
  promotion rate = promoted / new).

`yield_.py`

- `SourceYield(source_id, raw_hits, unique_candidates, promoted,
  promotion_rate, last_run_with_hits, last_productive_run, reading)` where
  reading is one of `earning_its_place` (promoted at least once),
  `high_volume_no_promotions` (20 or more candidates, none promoted),
  `low_volume` (fewer than 20, none promoted), `silent` (active source with no
  hit in any run). `compute_yield(sources, sightings, candidates,
  dispositions)`.

`coverage.py`

- `CoverageCell(row_id, column_id, count, status: CoverageStatus)`.
- `requirement_by_lane(requirement_set, reports, sources) -> matrix`: rows are
  requirements, columns are lanes; count is active reports with an assessment
  on the requirement whose source sits in the lane (reports with no source use
  the lane of their actor when known, else an `unattributed` column); the
  status of each ROW TOTAL uses `coverage_status(scanability, total)` so a
  blind spot is labelled from the requirement's scanability, never from the
  count alone. Cells themselves carry counts; a cell status is `covered` for 3
  or more, `thin` for 1 or 2, `quiet` for 0 unless the row is a blind spot.
- `taxonomy_by_count(taxonomy_axis, requirement_set, reports)`: rows are the
  axis nodes; count is active reports whose assessed requirements have the
  node in `expected_coverage` or which carry a hazard whose family is the node;
  `expected` is the number of requirements expecting the node; status
  `blind_spot` when expected is 0 and count is 0 (the framework does not
  foreground this ecosystem: say so), else via counts.
- `credibility_distribution(reports, run_id | None)`: counts per credibility
  digit, for the grade-inflation check.

`datecheck` already exists in intelligence; evaluation re-exports a summary
(`counts by kind`) for the snapshot.

## Dissemination (`backend/src/gwylio/dissemination/`)

`model.py`

- `Level` enum: strategic, operational, tactical. `Period(start, end, label)`.
- `Product(id, level, requirement_set_id, period, generated_on, sections:
  tuple[Section, ...], report_ids, method_note)`; `Section(heading, body:
  tuple[CleanText, ...] paragraphs, bullets: tuple[CleanText, ...])`.

`copy.py`

- Loads `config/copy.json` (add it: every heading and standing sentence used by
  the renderers, keyed; a `notes` field; register it with `gwylio schema`).
  Renderers may not contain literal headings or standing sentences; a test
  swaps a copy string and asserts the rendered output changes.

`render_intsum.py` (operational, a period of one month by default)

- Sections: Summary (counts: new reports, state changes, faded, verified, by
  direction; one sentence each, numbers in a short table rendered as Markdown);
  What moved (per requirement group of kind wbo, the reports created or
  changed in the period, each as one line: grading, title, direction tags,
  state); Threats and two-way signals first within each list (optimism guard
  made structural); Quiet and blind spots (requirements with no activity,
  labelled by `coverage_status`, with the standing sentence that a blind spot
  is not quiet); Verification due (date check findings); Method note (runs in
  the period with funnel totals, dispositions, non-government share of
  promotions, credibility distribution, instrument version). No prose is
  generated by a model; everything is assembled from data and copy.

`render_strategic.py` (annual picture per requirement set)

- Sections: Purpose (copy); per requirement: the standing picture (active
  reports by direction and state, top three by potential impact, grading
  spread, coverage status, scanability note verbatim); per WBO group: a
  question list drawn from the threatens and neutral reports' titles rendered
  as "What would change if ... ?" using a copy template (never
  recommendations); Coverage audit (both matrices as Markdown tables); Method
  note as above but for the year.

`tactical`: `render_tactical` raises `NotImplementedInV1` with the message
"tactical alerts are a designed seam, not built in v1"; the CLI exits 4 with
that line.

Markdown output: deterministic, no dashes (CleanText throughout), tables with
pipes, headings `##`. Written to `data/products/<level>_<period label>.md`
and the product recorded in the `product` table (migration 0003) and in
`data/exports/products.json`.

## CLI

- `gwylio audit [--set ID]`: prints both coverage matrices as tables plus the
  row statuses, and the credibility distribution.
- `gwylio yield`: prints the yield table, silent sources last.
- `gwylio product --level operational|strategic|tactical [--period YYYY-MM |
  YYYY] [--set ID]`: renders and records; prints the output path.

## Tests

  `blind_spot`; a `high` one with zero is `quiet`; a node no requirement
  expects is `blind_spot` at zero; counts reconcile with a hand-built report

are contexts: they import only `gwylio.shared` and themselves; the
infrastructure layer adapts repository rows into the plain inputs they take.
